# Codex Continuity 隐私说明

Codex Continuity 是本地插件，不提供云端账户、遥测或独立后端。

## 模型处理的数据

当符合条件的 Codex Turn 完成后，插件只向用户当前配置的 Codex provider／Endpoint 发送：

- 当前任务 ID 和原生标题；
- 上一条本地短章节和短进展；
- 官方 `Stop` payload 中 `last_assistant_message` 的有限内容。

这些内容只用于提取最新进展，并为标题持久化提供保守兜底。`Stop` 路径只请求不含 turns 的线程元数据，以确认任务身份、原生标题和是否属于子智能体；不会读取完整任务历史。插件不会把数据发送给 Codex Continuity 作者，也不会主动读取项目文件、API key 或登录数据库。

在一个具有非空工作目录的真正新任务首轮中，Continuity 会指示当前 Codex 使用原生任务工具读取任务标题与短摘要，并最多读取 3 个 `cwd` 完全相同的候选最近 2 轮用户输入与最终回复，用于判断是否存在唯一、高置信的可继续旧任务。无目录或没有同目录候选时，自动路径不会读取其他任务正文。只有用户主动要求查找其他项目或全部项目时，读取范围才会扩展到用户指定的目录范围。工具输出、推理和中间播报不作为匹配证据。这一判断由用户当前 Codex 模型和 provider 完成，不调用 Continuity 自有 Endpoint，不把数据发送给插件作者。任务内容始终按不可信数据处理，不当作指令执行。

后续用户提交时，`UserPromptSubmit` 只注入一段固定的工作路由与原生标题维护规则，不复制或保存原始 prompt。工作路由 Skill 复用当前 Codex 模型、当前请求和当前任务原本已有的上下文完成分类；它不读取其他任务，不另外调用分类模型，也不保存路由判断。只有当前根任务做出可靠结果并进入明确的新章节时，当前 Codex 才会调用一次原生标题工具；首轮、临时问题、同章节、小修、未完成、失败、阻断、子智能体、低置信度和显式锁定标题都保持不变。留在当前任务和低置信判断不产生提示。子智能体只有在用户直接批准、明确授予自动委派权限或更高优先级指令已授权时才使用 Codex 原生工具创建；聊天支线、新任务、回传和归档始终需要用户明确确认。插件不复制子智能体或分支的对话正文。

## ModelDial 公共配置证据

只有当工作路由已经选择 Codex 原生子智能体，或用户直接要求子智能体时，当前 Codex 才可能匿名读取 `https://modeldial.com/api/v1/radar/latest.json`。这是一个只读公共数据请求，不需要账号或 API key；请求不会携带用户原始请求、任务标题、代码、工作目录、当前模型配置、凭据或遥测。

ModelDial 只提供最新公开批次中的配置建议，不决定是否委派，也不会收到路由判断。主代理配置仅作为提示；子代理配置只有在 Codex 原生工具和当前项目规则允许时才会应用。网络失败、响应非法、字段缺失或策略冲突时，工作路由使用 Codex 当前允许的配置继续，不保存远端响应，也不阻断委派。

## 本地保存的数据

插件在当前用户的平台数据目录保存：macOS 为 `~/Library/Application Support/Codex Continuity Plugin/`，Windows 为 `%LOCALAPPDATA%\Codex Continuity Plugin\`，WSL／Linux 为 `${XDG_STATE_HOME:-~/.local/state}/codex-continuity-plugin/`。其中保存：

- 以哈希文件名分隔的任务状态；状态文件内保留对应任务 ID；
- 自动改名前后的标题；
- 对应 Turn ID；新的 `Stop` 路径不再生成消息 ID，旧版本已有账本中可能仍保留历史消息 ID；
- 最近可靠的短章节、短进展和置信度；
- 被撤销的标题和用户显式锁定状态；
- 不含对话正文的运行状态日志；日志会记录任务 ID、Turn ID 和处理结果，便于本地排错。
- 每个任务一个首轮识别 marker；有可靠目录时另有一个首轮同目录匹配 marker。文件名都使用任务 ID 的 SHA-256，内容只有 schema 版本和检查时间，不保存原始 prompt。
- 后续 Turn 的原生标题资格 marker；文件名使用任务 ID 的 SHA-256，内容只有 schema 版本、Turn ID 和写入时间，不保存原始 prompt、标题或对话正文。

macOS 与 Linux 的目录权限为 `0700`，状态和日志文件权限为 `0600`；Windows 使用当前用户 `LOCALAPPDATA` 的访问控制。数据默认保留到用户卸载插件并自行删除该目录；插件不会自动上传或同步这些文件。

## 用户控制

- 可在 Codex 的插件或 Hook 设置中停用自动标题维护。
- 相似任务只会作为建议；用户可以选择“继续旧任务”或“留在这里”，未选择前不发送、跳转或归档任何任务。
- 工作路由每次最多建议一种变更；用户明确说“就在这里做”会覆盖尚未执行的自动建议。没有直接批准、自动委派授权或更高优先级授权时不委派子智能体；Fork、新建、回传和归档始终等待明确确认。
- 聊天分支回传主线后默认保留；只有用户明确要求“回主线并归档”且回传成功后才归档。
- 可要求 Continuity 检查当前任务的标题状态。
- 每次自动改名都可以撤销；撤销只抑制该标题建议，不会静默关闭后续自动维护。
- 可明确锁定当前标题，也可恢复自动更新。

## 当前支持边界

插件支持 macOS 与 Windows 11，并依赖本机 Codex／ChatGPT Desktop 的 Codex runtime 和用户已经配置的 provider／登录状态。macOS 已完成真实 Desktop 验收；Windows 原生 PowerShell 路径在取消 beta 标记前仍需完成一次真实 Windows Desktop 验收。
